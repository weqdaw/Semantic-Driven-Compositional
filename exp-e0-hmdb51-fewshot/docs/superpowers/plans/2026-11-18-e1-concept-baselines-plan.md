# E1概念基线实现计划

用户已明确要求收束E0并实现下一阶段。按此前已提出的C0／C1＋匹配随机投影路线原地增量实现；当前没有Git，不新建无关checkout，以`.e1-backup/`快照保护既有文件。此次仅实现、测试及只读输入／文本编码冒烟，不执行正式E1特征准备或360组拟合，不修改外部Vault。

## 设计与接口

- 固定首版16个通用可见姿态概念，中文名称＋单条英文描述；由助手基于五类名称及一般姿态知识拟定，已知E0汇总结果作为开发背景。未按E1结果筛选提示，未使用最终测试；不是人工概念真值。保留可见性／未知边界。
- 冻结原生CLIP文本分支，与缓存图像分支的检查点、参数哈希、CLIP源码及联合嵌入维度核对。记录tokenizer及BPE文件哈希，77 token、拒绝截断。仅编码概念文本，不重新编码视频。
- 每帧`C=Z E^T`，E每行单位化；C为余弦，不做逐帧概念向量L2、不做softmax／阈值化／数据集标准化。C0=[均值,总体标准差]，C1增加6/5/5段均值；沿用逐块及整体L2、float64统计、float32保存。m=16时为32／80维。
- R0／R1使用5个固定PCG64种子0—4产生512×16的独立单位列随机方向，同一矩阵用于所有视频／K／支持集合，做与C0／C1完全相同的余弦及汇总。保存每种投影，不挑最佳。
- 引用原分组第二轮60组V0/V1；不再改变E0表示或重做划分。新增C0/C1各30组，R0/R1各150组，共360；报告共420组／同一50段的21000次重复评价。
- 主比较C0−V0、C1−V1、C1−C0、C0−R0、C1−R1，另报告概念时间增量减随机时间增量。随机控制先在同支持集合内平均指标，再跨10个支持集合统计；保存逐投影结果与配对。
- 新增`e1_features.py`、`e1_text.py`、`e1_experiment.py`、`e1_reporting.py`、`e1_cli.py`及脚本09。复用旧只读验证、岭分类和指标接口，不编辑任何既有Python源码，避免已有缓存代码身份失效。
- CLI分check（只读）、prepare（文本编码和派生缓存，无拟合）、run（显式development拟合）、summarize（独立复算）。生产阻断合成文本／图像及final_test；API合成夹具只能在双方均显式synthetic时使用。
- 保存概念库快照、E和投影矩阵、逐帧C、C0/C1/R0/R1、父输入证据摘要、文本冻结记录、代码／环境／配置及文件哈希。准备空白可见性审核模板，不伪造人工审核，不把含类名路径的表称严格盲审。

## 实施与验证顺序

1. 数值测试先失败：余弦无额外归一化、C0/C1字面预期、逆序敏感性、固定随机方向、非法输入／重复概念／冻结错配；实现特征及文本接口。
2. 合成端到端测试先失败：360组完整性、精确支持配对、控制种子平均、概念／投影与向量复算；实现独立缓存和运行器。
3. 增加缺组、错配、篡改、环境文件、概念快照、矩阵及生产CLI阻断测试；实现报告和命令入口。
4. 补充E0收束说明、E1详细指南、配置、数据契约及导航；不改历史运行产物。
5. 完整pytest；真实第二轮缓存只读check；原生文本分支冒烟（只在内存编码16条文本，确认同检查点及冻结状态，无任务拟合）；独立代码审查；原文件哈希保护、链接检查、验收记录。

## 审查重点
